## Путь запроса: три сценария

### 1. Ответ по регламенту
1. Сотрудник: *«Что делает координатор при неполных сведениях по проекту ИБ?»*
2. **analyze**: тип вопроса, область (дирекция, этап) понятна → уточнять не нужно.
3. **retrieve** → пп. 2.1–2.4 «Проектная деятельность Дирекции ИБ». Мало релевантного → **rewrite** и повтор (до 2 раз).
4. **check_scope**: пункт применим к дирекции и этапу из вопроса? Высокий балл поиска ≠ применимость.
5. **generate**: ответ с условиями и исключениями (*«более пяти рабочих дней»*), цитаты `[1]`, `[2]`.
6. **verify_citations**: цитата есть в тексте пункта, утверждение ею подтверждено.

### 2. Уточнение
1. *«Что будет, если по заявке не хватает информации?»* — правила разные в Дирекции ИБ и ДБРЦТ.
2. **analyze** находит развилку по факту, который знает только сотрудник → **clarify**: `status = needs_clarification`, вопрос *«Какая дирекция и какой этап: назначение РП в ИБ или пресейл в ДБРЦТ?»*. Ход заканчивается.
3. Ответ пользователя приходит с `history` → analyze склеивает исходный вопрос и уточнение → обычный путь сценария 1.
4. Неоднозначность осталась → `refused` с причиной «применимое правило определить нельзя».

### 3. Пополнение базы через службу качества
1. Вопрос без ответа в регламентах → **escalate**: backend создаёт **обращение** (один раз на вопрос сессии), агент отвечает `status = escalated` + номер обращения и что с ним будет.
2. Сотрудник качества (роль `quality`) видит очередь, пишет ответ, привязывает к регламенту/пункту, **подтверждает**.
3. Подтверждение → `qa_entry` публикуется в индекс как `source_type = qa_entry`.
4. Похожий вопрос из **новой сессии** → поиск находит запись → ответ со ссылкой «подтверждено службой качества, обращение №…, связано с п. X документа Y».

Каждый шаг уходит на фронт событием `step` — это видно жюри как агентность.

## Стек

| Слой | Выбор | Запасной вариант |
|---|---|---|
| LLM | **qwen3:8b** в Ollama (D-004) | qwen3:4b, если не хватит скорости |
| Запуск LLM | **Ollama нативно на Mac** (Metal). В docker на Mac GPU недоступен — контейнеры ходят к `host.docker.internal:11434` | llama.cpp server |
| Эмбеддинги | BAAI/bge-m3 (на Mac — CPU/MPS) | multilingual-e5-large |
| Реранкер | BAAI/bge-reranker-v2-m3 | без реранкера (корпус маленький) |
| Векторная БД | Qdrant | in-memory (4 документа — это сотни чанков) |
| Лексический поиск | BM25 — оставляем, если на контрольных вопросах даёт прирост | sparse-вектора bge-m3 |
| Парсинг | python-docx (корпус — только DOCX), docling | — |
| Агент | LangGraph | свой цикл на Python |
| Backend | FastAPI + SQLModel + SQLite | Postgres |
| Frontend | React + Vite + TypeScript + Tailwind | Streamlit (если горит) |
| Оценка | контрольные прогоны `eval/datasets/control.jsonl` + ручная сверка | — |
| Деплой | docker-compose для backend/frontend/qdrant + Ollama на хосте; стенд по URL (свой Mac + туннель или VPS) | скрипты запуска |
| Python | 3.12, **uv** | pip + venv |

## Железо

| Машина | Роль | Статус |
|---|---|---|
| Mac M4, 16 ГБ | разработка агента, первые прогоны Ollama | скорость не замерена |
| Mac, 24 ГБ | модель и демо-стенд | чип и скорость не проверены |

Ориентиры: `qwen3:8b` Q4 ≈ 5–6 ГБ памяти, bge-m3 + реранкер ≈ 2–3 ГБ. Готовность стенда проверяем **с реального устройства вне хоста** (стенд нужен по URL до 03.12).
