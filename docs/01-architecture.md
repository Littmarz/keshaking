# Архитектура

## Общая схема

```
┌───────────────┐   HTTP + SSE   ┌──────────────────── backend (FastAPI) 🧭 ────────────────────┐
│ frontend 🧭   │ ─────────────▶ │ /auth  /chat/ask/stream  /documents  /analytics  /feedback  │
│ React         │ ◀───────────── │   │ мок-юзер → роль → разрешённые access_level               │
│ чат, цитаты,  │  события шагов │   ▼                                                           │
│ аналитика     │                │ agent_service ──▶ agent.run_agent_stream(question, user) 🤖 │
└───────────────┘                │   │                                                           │
                                 │   ▼ пишет каждый шаг и итог                                   │
                                 │ SQLite: messages, query_logs, agent_steps, feedback           │
                                 └───────────────┬───────────────────────────────────────────────┘
                                                 │ analytics/ 🔎 читает логи → отчёты, графики
                                                 ▼
┌──────────────────────────── agent (LangGraph) 🤖 ────────────────────────────┐
│ analyze → plan(подвопросы) → retrieve ⇄ rewrite → check_actuality →          │
│ check_conflicts → generate(с цитатами) → verify_citations → answer | refuse  │
│                 │ tool: search()            │ tool: get_document_versions()   │
└─────────────────┼───────────────────────────┼─────────────────────────────────┘
                  ▼                           ▼
┌──────────── retrieval 🔎 ────────────┐   ┌─────────── ingest 📄 ──────────────┐
│ BM25 + bge-m3 → RRF → bge-reranker   │◀──│ файлы → парсинг → чанки по пунктам │

│ Qdrant (docker)                      │   │                                    │
└──────────────────────────────────────┘   └────────────────────────────────────┘

LLM: Ollama (разработка) / vLLM (демо) — OpenAI-совместимый API на localhost
```

## Путь одного запроса

1. Пользователь (мок-логин «Петрова, отдел продаж») пишет: *«Кто подписывает агентский договор свыше 1 млн?»*
2. Frontend → `POST /chat/ask/stream` (SSE).
3. Backend достаёт пользователя → роль → список доступных уровней документов → вызывает агента.
4. Агент:
   - **analyze**: тип вопроса (факт / процесс / сравнение / многорегламентный), нужно ли разбить.
   - **plan**: подвопросы, например «порядок подписания договоров» + «лимиты полномочий».
   - **retrieve**: для каждого подвопроса `search()` → топ-k чанков. Мало релевантного → **rewrite** запроса и повтор (до 2 раз).
   - **check_actuality**: отбросить устаревшие редакции, при сомнении отметить.
   - **check_conflicts**: если два действующих пункта говорят разное → статус `conflict`.
   - **generate**: ответ строго по контексту с цитатами `[Документ, п. X.Y]`.
   - **verify_citations**: каждое утверждение подкреплено цитатой? Нет → перегенерировать или отказать.
5. Каждый шаг уходит на фронт событием `step` (видно «как агент думает» — это и есть агентность на демо).
6. Итог `result` → карточка ответа, чипы цитат, клик → документ с подсветкой пункта.
7. Backend пишет лог: вопрос, статус, скоры, цитаты, время, шаги. Пользователь ставит 👍/👎.
8. Дашборд: неудачные поиски, топ тем, «чего нет в базе», время ответа.

## Стек

| Слой | Выбор | Запасной вариант |
|---|---|---|
| LLM | Qwen3-8B / Qwen3-14B / Qwen3-30B-A3B (решает 🤖 разработчик 4 по бенчмарку) | T-lite / T-pro (Т-Банк), Vikhr |
| Запуск LLM | Ollama (разработка), vLLM (демо, быстрее) | llama.cpp server |
| Эмбеддинги | BAAI/bge-m3 | multilingual-e5-large |
| Реранкер | BAAI/bge-reranker-v2-m3 | без реранкера |
| Векторная БД | Qdrant | Chroma, FAISS |
| Лексический поиск | BM25 | sparse-вектора bge-m3 в Qdrant |
| Парсинг | docling, PyMuPDF, python-docx | unstructured |
| Агент | LangGraph | свой цикл на Python |
| Backend | FastAPI + SQLModel + SQLite | Postgres |
| Frontend | React + Vite + TypeScript + Tailwind | Streamlit (если горит) |
| Оценка | свой скрипт + LLM-судья, идеи из RAGAS | ручная разметка |
| Деплой | docker-compose | скрипты запуска |
| Python | 3.12, менеджер **uv** | pip + venv |

## Железо

Нужна хотя бы одна машина с NVIDIA GPU (**от 16 ГБ VRAM** комфортно, от 8 ГБ — с квантизованной 8B-моделью). Ориентиры:

| Модель | VRAM (примерно) |
|---|---|
| Qwen3-8B, квант Q4 (Ollama) | ~6 ГБ |
| Qwen3-14B, Q4 | ~10 ГБ |
| Qwen3-30B-A3B (MoE), Q4 | ~19 ГБ |
| Qwen3-8B, FP16 (vLLM) | ~17 ГБ + кэш |
| bge-m3 + реранкер | ~2–5 ГБ (можно и на CPU, медленнее) |

Без GPU у команды → аренда на время хакатона (решает капитан в день 1).
