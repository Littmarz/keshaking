# 🤖 Разработчик 4 — Агент и LLM

> **Простыми словами:** ты пишешь «мозг»: локальная LLM плюс программа, которая рассуждает в несколько шагов. Она разбивает сложный вопрос на части, ищет (через `search()` от 🔎), если найдено мало — переформулирует и ищет снова, отбрасывает устаревшие редакции, замечает противоречия, пишет ответ **только по найденным пунктам с цитатами**, сама проверяет цитаты, а если ответа нет — честно отказывает.
> **Твоя зона:** `agent/` + сервис LLM в docker-compose
> **Главные метрики:** правильность ответа ≥ 0.8, точность цитат ≥ 0.95, выдумок ≈ 0.
> **Критерий жюри:** **«Агентность» — от 0 (один запрос к модели) до 3 (автономный многошаговый агент). Нам нужно 3, это прямо твой критерий.**
> **Нагрузка:** спринт 48 ч (26.11 10:00 → 28.11 12:00 МСК), реально ~30–34 ч кода; P2 не делаем.

### Python-пакеты (в `sandbox/agent/`)

```bash
uv init && uv add langgraph langchain-core langchain-openai openai pydantic tenacity rapidfuzz rich
```

| Пакет | Зачем |
|---|---|
| **langgraph** | граф агента: узлы, условные переходы, состояние, стрим |
| **langchain-openai** / **openai** | клиент к OpenAI-совместимому API (его дают и Ollama, и vLLM) |
| **pydantic** | JSON-ответы LLM по схеме |
| **tenacity** | ретраи при невалидном JSON / таймауте |
| **rapidfuzz** | проверка, что цитата реально есть в тексте пункта |
| **rich** | цветной вывод шагов в консоли при отладке |

## 7. Граф агента (цель — 3 балла)

```
 вопрос ─▶ analyze ─▶ (не по теме) ─▶ refuse
              │
              ▼
            plan  (1–4 подвопроса)
              │
   ┌──▶ retrieve ── tool: search(allowed_access = права пользователя)
   │        │
   │      grade  (оставить релевантные)
   │        │ мало и раундов < 2
   └── rewrite
            │ хватает / раунды кончились
            ▼
    check_actuality ── tool: get_versions → выкинуть устаревшее, записать в dropped     👥 П1
            │
    check_conflicts ── противоречие → правило D-003 или статус conflict                 👥 П1
            │
     пусто? ──да──▶ refuse (причина + где искали + ближайшее найденное)
            │ нет
         generate  (ответ с [1], [2]… только по kept)
            │
          verify ──не прошла (1-й раз)──▶ generate с замечаниями
            │   ──не прошла (2-й раз)──▶ partial / refuse
            ▼
        finalize → AgentResult
```

Каждый узел пишет `AgentStep` с понятным `title` — его видит жюри в интерфейсе:
- «Разбил вопрос на 2 части: порядок подписания · лимиты полномочий»
- «Нашёл 8 фрагментов, подходят 3»
- «Переформулировал запрос: “полномочия на подписание договоров”»
- «Отбросил “Регламент…, ред. 2” — заменён ред. 3 от 01.03.2026»
- «Проверил ответ: 2 утверждения, оба подтверждены цитатами»

### Правила

- **Цитаты проверяем кодом**: `quote` должна реально быть в тексте пункта (rapidfuzz ≥ 90%). Нет → утверждение не подтверждено.
- **Лимиты:** ≤ 4 подвопроса, ≤ 2 переформулировки на подвопрос, общий таймаут. Иначе ответ идёт минуту.
- **Служебные шаги** — короткие промпты, `temperature=0`, JSON, без thinking. **Генерация** — больше контекста.
- **Отказ — это фича**: «В доступных документах нет ответа о X. Искал в: … Ближайшее найденное: … Рекомендуем обратиться к …».
- Нет прав на нужный документ → не пересказываем его, а говорим «документ есть, но у вас нет доступа».
- `history` — для уточнений («а если сумма меньше?») → на шаге analyze переписываем в самостоятельный вопрос.

## 9. Риски

| Риск | Что делать |
|---|---|
| Ответ идёт 1+ минуту | Служебные шаги без thinking и коротко; маленькая модель для grade, большая для generate; vLLM на демо |
| LLM ломает JSON | structured output + pydantic + ретрай + запасной парсинг |
| Модель отвечает «из головы» | Жёсткий промпт + verify + проверка цитат кодом; лучше отказ, чем выдумка |
| `num_ctx` в Ollama по умолчанию маленький → контекст молча обрезается. Через OpenAI-совместимый `/v1` его **не передать** | `OLLAMA_CONTEXT_LENGTH=16384` у сервера Ollama, или Modelfile с `PARAMETER num_ctx`, или нативный `/api/chat` с `options.num_ctx` |
| Ответ на английском или смесь | System-промпт «только по-русски» + русские few-shot |
| Модель не влезает в VRAM на демо-машине | Квант Q4, запасная модель меньше — решаем в бенчмарке |
| Граф стал сложным, всё ломается | Сначала наивный RAG → узлы добавляем по одному, после каждого — `make eval` |
