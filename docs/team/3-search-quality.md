# 🔎 Разработчик 3 — Поиск и замер качества

> **Простыми словами:** ты пишешь две вещи.
> 1. **Поиск:** по вопросу пользователя достаёт из индекса нужные пункты действующих документов, к которым у пользователя есть доступ. Этим пользуется агент.
> 2. **Измерения:** код, который прогоняет всю систему по тестовым вопросам и считает цифры (нашли ли нужный пункт, правильный ли ответ, верны ли цитаты, сколько секунд), и код аналитики по логам (неудачные поиски, чего нет в базе, топ тем).
> **Твоя зона:** `retrieval/` (поиск) · `eval/` · `analytics/`
> **Главная метрика:** Recall@5 ≥ 0.9 — нужный пункт в топ-5.
> **Нагрузка:** спринт 48 ч (26.11 10:00 → 28.11 12:00 МСК), реально ~30–34 ч кода; P2 не делаем.
> ✅ **Спринт идёт с 10:00 26.11.** Требования — [../00-conditions.md](../00-conditions.md), контракты — [../02-contracts.md](../02-contracts.md). Разделы ниже про подготовку (21–25.11) — история; актуальное — «Обновление 26.11».

**Почему это важно:** критерий жюри «Соответствие задаче партнёра» прямо требует аналитику (неудачные поиски, что ищут, чего нет в базе). А «измеримое качество» мы сами обещали в заявке — без твоих цифр это просто слова.

## 7. Ключевые решения (продумать до ТЗ)

### Конвейер поиска

```
вопрос → query.py (леммы, синонимы)
       ├─▶ lexical (BM25)   top-30 ─┐
       └─▶ dense (Qdrant)   top-30 ─┴─▶ RRF → top-30 → reranker → top-k (по умолчанию 8)
фильтры (status, access_level, doc_ids) — применяются в Qdrant и после BM25
```

### Порог «ничего не нашли»

Лучший скор реранкера ниже порога → сигнал агенту «ответа, скорее всего, нет» и запись «неудачный поиск». Подбираешь порог на `dev.jsonl` по вопросам `no_answer` vs остальным.

### Метрики (цели)

| Метрика | Как считаем | Цель |
|---|---|---|
| Recall@5 | хоть один ожидаемый пункт в топ-5 | ≥ 0.9 |
| MRR | 1 / позиция первого правильного | ≥ 0.75 |
| Правильность ответа | LLM-судья 0/1 + ручная проверка 20 случайных | ≥ 0.8 |
| Точность цитат | цитата дословно (≥ 90% по rapidfuzz) есть в пункте и пункт ожидаемый | ≥ 0.95 |
| Верный статус | отказ / конфликт / новая редакция там, где надо | ≥ 0.9 |
| Время | p50 / p95 | p50 < 15 с |

Тюним на `dev`, в отчёт — `test`.
