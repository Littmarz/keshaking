## ⛔ Главное правило: до 10:00 МСК 26.11 код не пишем

Дословно из FAQ: *«Нельзя одно: писать код. Разработка продукта идёт с 10:00 26 ноября»*.

| Можно до старта | Нельзя до старта |
|---|---|
| Изучать описание задачи, анализировать | Писать код — ни в репо, ни «в песочнице», ни «черновиком» |
| Проектировать: макеты, схемы, архитектура, сценарии **текстом** | Переносить в решение что-то, написанное до старта |
| Завести репозиторий, аккаунты и ключи у поставщиков моделей и хостинга | Класть в документы готовые куски кода «чтобы потом скопировать» |
| Установить инструменты, скачать модели и docker-образы, пройти туториалы | |

Конкурсной разработкой признаётся **только код, созданный в ходе спринта**, и продукт не должен быть развитием ранее существующего.
Поэтому контракты в [02-contracts.md](02-contracts.md) описаны таблицами полей, а не кодом.

## Что сдаём

Развёрнутый стенд и работающий URL **не нужны**.

1. **Демо-видео до 3 минут**, записанное **одним фрагментом без монтажа**, на данных задачи.
2. **Описание продукта на одну страницу** по шаблону из личного кабинета (шаблон появится со стартом спринта). Разделы:
   - подход и архитектура;
   - стек и модели (**название модели обязательно**);
   - принцип работы;
   - реализованная и нереализованная функциональность;
   - **расчёт стоимости эксплуатации и внедрения**;
   - использованные наработки и компоненты третьих лиц (с лицензиями).
3. **Ссылка на репозиторий.** ⚠️ В FAQ противоречие: в одном месте «открытый», в другом «закрытый, доступ запросят до определения победителей». См. вопрос в [05-questions-to-organizers.md](05-questions-to-organizers.md). Сервис любой (GitHub или российский аналог).

### Видео: правила

| Можно | Нельзя |
|---|---|
| Субтитры, подписи, стрелки-пояснения | Склейки, нарезку, любой монтаж |
| Голосовой комментарий, окно с камерой в углу | Длиннее 3 минут |
| Записывать окно приложения, а не весь экран | Заменять показ работы слайдами |
| **Ускорять фрагменты ожидания ответа модели** | Показывать функциональность, которой нет (её — в «нереализованное») |

Видео должно отражать фактическую работу продукта — отправляя продукт, мы это подтверждаем.

## Задача партнёра

Сотрудники тратят 30 мин – 2 ч на поиск информации о внутренних процессах (кто подписывает агентский договор, какой регламент действует, кто ответственный за этап). Информация разбросана по регламентам, приказам, базам знаний. 100–300 таких запросов в месяц = 50–300 человеко-часов. До 40% запросов остаются без ответа или получают устаревшую информацию → ошибки в документах, задержки согласований, повторная работа.

Наша мотивация (из заявки): сократить время поиска, снизить ошибки из-за устаревших правил, ИИ-агент во внутреннем контуре, ответы со ссылками на конкретные пункты, измеримое качество, готовность к пилоту.

## Логика и функциональность

- Отвечать в том числе на вопросы, затрагивающие **несколько регламентов**.
- При противоречиях логику выбирает команда. **Обоснованный отказ** с источниками и причиной неопределённости допустим.
- Права доступа сотрудников — не обязательно, но **плюс** на демо.
- Интеграция с корп. системой допустима, идентификацию пользователя можно **имитировать**.
- Действия по итогам ответа (создать заявку и т.п.) — не требуются.

## Модели и инфраструктура

- Серверов, моделей, ключей и лимитов организатор **не даёт**. Списка разрешённых моделей нет.
- Для нашей задачи решение должно работать **во внутреннем контуре** — с **локальной моделью**, без внешних LLM API.
- Открытые библиотеки, фреймворки, модели можно — при соблюдении лицензий, **перечень указываем при сдаче**.
- Решение **не должно быть дорогим в эксплуатации** (и это прямо считается в описании продукта).
- Для разработки можно любые инструменты и внешние API (например, сгенерировать синтетику). Работа решения и демо — в изолированном контуре.

## Оценка — 6 равновесных критериев (Приложение 1)

Отдельных критериев приёмки по каждой задаче нет — единые критерии Приложения 1. Известны:
1. **Соответствие задаче** — смотреть, какой результат закладывает заказчик. Релевантность + аналитика: разбор неудачных поисков, что ищут пользователи, чего нет в базе, логирование, аналитика по поиску.
2. **Агентность** — от 0 (один запрос к модели) до **3 (автономный многошаговый агент)**. Целимся в 3.

- Скорость отдельно не оценивается, но входит в корректность реализации.
- Методика сравнения ответов с эталоном не задана.

Остальные 4 критерия неизвестны → см. [05-questions-to-organizers.md](05-questions-to-organizers.md).
