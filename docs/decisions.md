### D-003. Применимость и конфликты (пересмотрено 26.11)
- Дата / кто: 26.11 / команда (черновик от 21.11 заменён)
- Контекст: заказчик оставил правила команде. Разные дирекции **правомерно** применяют разные процедуры, поэтому «более поздний документ главнее» как универсальное правило не подходит. Редакций и дат вступления в корпусе нет
- Решение, по порядку:
  1. **Область действия**: сначала определить дирекцию и этап из вопроса. Не хватает факта → уточняющий вопрос (сценарий 2), а не выбор наугад
  2. Применяем только пункты своей дирекции и этапа; чужие не цитируем
  3. Явная пометка «утратил силу» / «отменён» / подтверждённая замена → `cancelled` / `superseded`, пункт исключается
  4. Статус `unknown` (дат нет) — пункт **участвует** в поиске
  5. Два применимых источника противоречат, правило не решает → `conflict`: показываем оба и объясняем неопределённость (организаторы это допустили)
- Почему: так работает компания; ошибка «ответил по правилу чужой дирекции» хуже честного уточнения

### D-004. Модель — qwen3:8b в Ollama на Mac
- Дата / кто: 26.11 / разработчик 4
- Контекст: NVIDIA нет; есть Mac M4 16 ГБ (разработка) и Mac 24 ГБ (демо). Нагрузка до 200 запросов в день
- Решение: `qwen3:8b` в Ollama нативно (Metal), OpenAI-совместимый `/v1`. vLLM не используем. Служебные шаги — без thinking, JSON по схеме
- Почему: влезает в память обеих машин вместе с bge-m3; дешёвая эксплуатация. **Скорость на обеих машинах ещё не замерена** — запасной вариант `qwen3:4b`

### D-005. Пополнение базы через службу качества
- Дата / кто: 26.11 / команда
- Контекст: сценарий 3 карточки — «дообучение» через ответ сотрудника качества
- Решение: не дообучаем модель, а **пополняем поисковую базу**: локальная очередь обращений → форма ответа с привязкой к регламенту → подтверждение → запись `qa_entry` в индексе. Только подтверждённые записи участвуют в ответах. Одно обращение на вопрос (dedup по сессии и нормализованному вопросу). Обращение создаёт backend, не LLM
- Почему: прозрачно и проверяемо (источник виден в цитате), не нужен GPU для обучения, знание появляется сразу после подтверждения

### D-009. Подтверждённое знание службы качества важнее пункта регламента
- Дата / кто: 27.11 / команда
- Контекст: ответ организаторов в чате задачи (27.11, 01:10): при противоречии ответа эксперта качества и регламента «приоритет у качества, регламент может быть в актуализации»
- Решение: поиск поднимает подтверждённые `qa_entry` выше пунктов регламента при близком совпадении; агент при расхождении отвечает по записи качества и **показывает, что регламент говорит иначе** (обе цитаты, пометка «регламент, вероятно, на актуализации»)
- Почему: так работает заказчик; сотрудник видит и актуальный ответ, и причину расхождения

### D-010. Эскалация — локальная очередь + письмо в тестовый ящик
- Дата / кто: 27.11 / команда
- Контекст: карточка допускает письмо на адрес службы качества; организаторы: «достаточно почтового ящика», для тестов — Mailpit
- Решение: обращение создаётся в локальной очереди (`tickets`) и дублируется письмом в Mailpit (docker-сервис, SMTP 1025, веб 8025). На видео показываем письмо в Mailpit и форму ответа качества
- Почему: ровно формулировка карточки «отправлять письмо на адрес службы качества», без реальной почты
