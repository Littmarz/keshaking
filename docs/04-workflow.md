# Как работаем

## Git

- Репо команды: [ilya-nikiforov/keshaking](https://github.com/ilya-nikiforov/keshaking). На сдачу, по свежему объявлению, — **публичный HTTPS с историей** + хэш финального коммита (капитан сверяет в форме, вопрос №11).
- **Материалы заказчика (4 DOCX, PDF брифинга) в git не кладём** — только локально в `data/raw/`.
- Push, PR и любые изменения на GitHub из чужой рабочей копии — только с явного подтверждения её владельца.
- `main` защищён: только через PR, минимум 1 ревью. В последние 12 часов спринта допускаем самоапрув мелких фиксов, чтобы не ждать.
- Авторы коммитов — только участники команды, каждый под своим git-аккаунтом.
- Ветки: `feat/<папка>-<что>`, `fix/<папка>-<что>`, `docs/<что>`. Пример: `feat/retrieval-reranker`.
- Коммиты: `retrieval: add bge reranker`, `backend: sse endpoint`. Коротко, по-английски или по-русски — без разницы, но одинаково.
- **Не коммитим**: `data/`, `models/`, `.env`, `*.gguf`, `*.safetensors`, `node_modules/`, `.venv/`, `qdrant_storage/`.
- `core/schemas.py` и `docs/02-contracts.md` меняются только с ревью двух человек (автор модуля-потребителя + капитан).
- В корне есть `.dockerignore` (создаём 26.11 вместе с Dockerfile): `models/`, `data/`, `node_modules/`, `.venv/` не должны уходить в docker build.

## Код — только в спринте

Конкурсной разработкой считается код, написанный с 10:00 26.11. Заготовок до старта в решение не переносим. В `sandbox/<твоё_имя>/NOTES.md` — заметки.

## Порядок интеграции

1. Сквозной прогон на заглушках (mock-агент, mock-поиск).
2. Тот же сценарий на реальных DOCX и локальной модели.
3. Цитаты проверяем кодом (есть в тексте пункта) и **вручную** — подтверждают ли они вывод.
4. Ошибки связи с моделью или поиском — показываем как технические ошибки, не как ответ агента.

## Синки

- **Ежедневно, 15 минут** (время выбирает капитан): сделал / делаю / блокер.
- Блокер больше 1 часа — сразу пишем в чат, не ждём синка.
- Задачи: GitHub Projects (доска To do / In progress / Review / Done). Одна задача = одна ветка = один PR.

## Стиль кода

- Python 3.12, `uv`, `ruff` (линтер + форматтер), type hints везде, pydantic v2.
- Frontend: TypeScript strict, ESLint + Prettier.
- Каждая папка-модуль: свой `README.md` с запуском и примерами.
- Конфиг только через `.env` / pydantic-settings, никаких захардкоженных путей и URL.

## Журнал решений

Любое неочевидное решение (почему эта модель, как выбираем редакцию, что делаем при противоречии) — 3–5 строк в [decisions.md](decisions.md). Это готовый материал для описания продукта и ответов жюри.

## Компоненты третьих лиц

Каждую библиотеку, модель и образ, который реально используем, сразу вписываем в [third-party.md](third-party.md) с лицензией. По условиям этот перечень обязателен при сдаче.
