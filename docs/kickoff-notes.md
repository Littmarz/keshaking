# Кик-офф 26.11 — что сказал заказчик (конспект)

> Источник: **неофициальная** автоматическая расшифровка записи кик-оффа, выложенная участником в чат задачи 27.11 («организаторы не против»). Возможны ошибки распознавания. Сама расшифровка в репозиторий не кладётся — здесь наш пересказ.
> Говорят: Дмитрий Ширшов (директор по качеству Софтлайн) и Юлия Чердакова (заместитель). При расхождении с карточкой — опираемся на карточку; но здесь много уточнений, которых в карточке нет.

## Самое важное (меняет решения)

| # | Что сказал заказчик | Что это значит для нас |
|---|---|---|
| 1 | **Эскалация — письмом.** Бот сам создаёт письмо на адрес службы качества и **подключает пользователя в копию**; дальше переписка идёт по почте. «Локального кабинета службы качества недостаточно — им не будут пользоваться». Номер обращения «особо не нужен» | Письмо в службу качества (на демо — Mailpit / тестовый ящик, свои ящики разрешены) — **обязательно**; локальная очередь — только служебное хранилище. D-010 пересмотрено |
| 2 | **Ответ эксперта из почты агент обрабатывает сам**: понимает, что ответ финальный, и кладёт его в базу знаний (или в «Частые вопросы»). Имитация допустима. Отдельного подтверждения не нужно — отвечает менеджер по качеству или владелец процесса | Цикл сценария 3: письмо-ответ → разбор → `qa_entry`. На демо можно имитировать входящее письмо |
| 3 | **Не дословные цитаты.** Ответ — человеческим языком, кратко, **без искажения смысла**; по каждому утверждению — ссылка на источник («фраза — ссылка, фраза — ссылка»). Не переписывать регламент целиком | Генерация: краткая выжимка + ссылки на пункты; проверка цитат — по смыслу, quote остаётся для подсветки |
| 4 | **Уточнение — обязательно, когда от подразделения зависит ответ** (ИБ / ДБРЦТ / Техдирекция похожи, но различаются). Не усреднять («три дня и две недели → пять дней» — неверно). Проект может быть **комплексным** (две дирекции) → оба требования отдельно | Подсказка `ambiguous_scope` + clarify в агенте. Примеры из Q&A: срок инициации расчёта (ДБРЦТ 1.5 — 3 раб. дня, Техдирекция 1.5 — 2 недели), бюджетная оценка в конкурсе (ДБРЦТ 2.4 — кроме RFI, Техдирекция 2.4 — без исключения), старт работ без договора |
| 5 | **Не больше 2–3 итераций уточнения.** Если сотрудник не знает подразделение — показать **все применимые варианты с источниками**; если и после этого непонятно — в службу качества | Лимит раундов clarify = 2; после — варианты списком, затем `escalated` |
| 6 | **Вопросы не про регламенты** (маржа/премия по сделке, «сделай мне фоллоуап», курс доллара) — не отвечать: «вопрос не касается корпоративной базы знаний, обратитесь к руководителю» | Отдельный исход: отказ «вне базы знаний» **без** эскалации в качество (D-011) |
| 7 | **Противоречие между регламентами** → неоднозначный ответ и отправка в службу качества. «Спорный» ответ (уверенность не 100%) — давать **с оговоркой** (так решило руководство) | `conflict` → показать оба источника + письмо в качество; `partial` с оговоркой |
| 8 | **Неверный ответ хуже лишней эскалации.** «Лучше отправить в качество, чем дать неверный ответ» | Порог эскалации — консервативный |
| 9 | **Скорость:** «минуту ни один пользователь ждать не будет»; текущий бот отвечает за секунды | Минимум вызовов LLM, стрим шагов, быстрый поиск; задержку меряем в eval |
| 10 | Все 4 документа **действующие**. Доступ на чтение — у всех сотрудников, **разграничение прав не нужно** | Права доступа — убрать из планов (П5) |
| 11 | Ссылки на другие регламенты в DOCX вычищены; если пункт ссылается на документ, которого нет, — **назвать этот документ** | Агент: «ответ содержится в регламенте „…“» без ссылки |
| 12 | Эталонного набора не будет; **эталоном выступит служба качества** (проверят ответы сами). LLM-судья — на усмотрение | Наш контрольный набор + ручная проверка |
| 13 | Сейчас регламенты — wiki в **Confluence** (~100–300 регламентов), бот интегрирован в **Dion**; веб-решение лучше встраиваемое. Аналитика: повторяющиеся вопросы, обращения без ответа, проблемные разделы, востребованные документы — «полезно всё» | Потенциал внедрения: Confluence → индекс, Dion/почта → канал; аналитика — P2, но список метрик ясен |
| 14 | Экономику считает техническое подразделение; заказчику важны три сценария, «гнаться только за дешевизной не стала бы» | Экономика — по токенам за запрос (организаторы), без экстрима |

## Примеры «трудных» вопросов от заказчика

- Командировки: компенсация такси в выходной/праздник (трудовой и налоговый нюанс) — **вне наших 4 документов** → эскалация.
- «Какая у меня будет маржа/премия по сделке?» → вне базы знаний, к руководителю.
- «Что должен делать руководитель проекта?» → зависит от направления → уточнить.
