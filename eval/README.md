# eval/ — контрольные прогоны

**Владелец:** 🔎 Разработчик 3 · **Формат:** [../docs/02-contracts.md §7](../docs/02-contracts.md)

Эталонного набора от организаторов **нет**. Ведём свой: [datasets/control.jsonl](datasets/control.jsonl) — 35 сценариев по 4 DOCX. Правило из чата: вопросы **не прямым переформулированием требований**, а по двум паттернам — абстрактный вопрос без контекста и «другими словами» (синонимы, аббревиатуры, английский).

| id | Что проверяем |
|---|---|
| c01, c02 | уточнение: один исходный вопрос → разные дирекции → разные пункты (ИБ 2.2–2.4 / ДБРЦТ 1.1.1) |
| c03 | ответ из двух регламентов, у каждой части свой источник |
| c04 | граница «ровно 30%» в п. 1.3 пресейла ИБ |
| c05, c06 | простые ответы по Техдирекции (пункты 1.2 и 1.3 сверены с DOCX) |
| c07, c08 | эскалация → подтверждение службой качества → ответ на перефразированный вопрос из новой сессии |
| c09 | конфликт / отменённый пункт — только на тестовой копии индекса |
| c10, c11, c16 | «другими словами»: «проджект менеджер», вопрос на английском, «ЗНП» и «квал анкета» |
| c12 | одинаковое правило в двух дирекциях — уточнять **не** нужно, цитировать оба |
| c13 | «абстрактно»: «Сколько дней дают на расчёт?» → уточнение |
| c14, c15 | одиночные ответы с условием (срок действия расчёта, заявка за 3 рабочих дня) |
| c17–c31 | по одному-два вопроса на каждый документ: условия, исключения, сроки, запреты; «ПМ», «presale architect», английский |
| c24, c33 | уточнение: смета (ИБ 11.1 / ДБРЦТ 10.2), «кто назначает руководителя проекта» (Техдирекция 4.1) |
| c32 | одинаковое правило в двух дирекциях (анкетирование — Менеджер по качеству) |
| c34, c35 | вопросы вне регламентов (лицензия при реорганизации — пример со слайда брифа; дресс-код) → эскалация |

Что ещё проверяет прогон поиска:
- **подсказка уточнения** `ambiguous_scope` на первом ходе: `clarify` → должна быть, `single/synonym/boundary` → не должна;
- **подсказка «ответа нет»** `low_confidence` на сценариях с `expect_low_confidence`;
- **сценарий 3**: у c07 есть `qa_confirm` — прогон убеждается, что записи качества нет до подтверждения, публикует учебный ответ во **временное** хранилище, и c08 (тот же смысл другими словами) должен найти `qa_entry` первым.

По каждому прогону фиксируем: точность вывода, корректность цитат (есть в тексте и подтверждают вывод), правильность уточнения / эскалации / отказа, задержку. Задержки и объём запросов — в калькулятор стоимости.

## Запуск

```bash
python -m eval.run                      # поиск: hit@k, recall@k, MRR, утечки чужих дирекций → eval/reports/
python -m eval.run --only c04,c13       # отдельные сценарии
python -m eval.run --target agent       # когда появится agent.run.run_agent (статусы по ходам, факты, источники)
```

Только стандартная библиотека. Отчёт — markdown в `eval/reports/<дата>_<target>.md`, строка метрик — в `eval/reports/progress.jsonl`.

```
eval/
├── datasets/control.jsonl
├── run.py        ✅ прогон по turns (многоходовые — в одной сессии, c08 — в новой)
├── metrics/      citations · status · latency
├── report.py     таблица по сценариям + худшие ошибки
└── reports/
```
